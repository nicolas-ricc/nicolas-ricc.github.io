## Decisiones técnicas (declaradas)

1. **Parámetro sin uso → prefijo `_`.** En `maltings.test.ts:229` el replacer de `JSON.stringify` necesita `(k, v)` por posición. TypeScript exime de `noUnusedParameters` a los parámetros que empiezan con `_`, así que se renombra a `_k`. No se cambia la lógica.
2. **Imports sin uso → se borran**, no se silencian. Si un import trae solo nombres sin uso, se borra la línea entera; si trae otros, solo el nombre.
3. **El test de los flags vive en `scripts/tsconfig.test.ts`**, junto a los otros tests de repo (`scripts/agent-docs.test.ts`, `scripts/index-html.test.ts`). `tsconfig.json` es JSON válido (sin comentarios), así que basta con `JSON.parse`.
4. **No se agrega un test que corra `tsc`.** El typecheck ya corre en CI (`.github/workflows/deploy.yml`, `npm run typecheck` antes de `npm test`). El test de Vitest solo fija que nadie apague los flags.

## Review Focus

1. Que el comportamiento no cambie: solo se borran imports/nombres sin uso y se renombra un parámetro. Lo cubren los tests existentes de `barrio-monoblock`, `district`, `fair`, `maltings` y `city`, que se corren sin tocar sus aserciones.
2. Que `npm run build` siga pasando (Vite no hace typecheck, pero el bundle cambia si se borra un import con efectos). Ninguno de los imports borrados tiene efectos laterales (son nombres de módulos puros de `src/iso`, `src/map`, `src/scenes`); se corre `npm run build` en la Task 2.
3. Que el borrado de la guarda de #50 no deje volver `brokenTone`: con `noUnusedLocals` prendido, un import sin uso de `brokenTone` en `city.ts` rompe `npm run typecheck`. Se verifica a mano en la Task 2, Step 6.
4. Que `vite.config.ts`, `vitest.config.ts` y `scripts/` (incluidos por `tsconfig.json`) también queden limpios: lo cubre `npm run typecheck`, que compila todo el `include`.
5. Que no se callen los flags con ningún truco (`// @ts-ignore`, `// @ts-expect-error`, `void x;`, exports artificiales): se revisa en el diff.

## Assumptions

1. **Errores que aparezcan si la base se mueve** se limpian en la Task 1 con las mismas reglas; no se abre otro issue. El issue pide limpiar en el mismo cambio lo que marquen los flags. Descartado: abortar o abrir un follow-up.
2. **`import type` no deja import en runtime.** TypeScript siempre borra `import type`. `tsconfig.json` no prende `verbatimModuleSyntax` ni `isolatedModules`, y el archivo afectado es un test. Descartado: verificarlo con el bundle.
3. **`scripts/tsconfig.test.ts` existe aunque el issue no lo pide.** Hace ejecutable el criterio "flags prendidos" y evita que alguien los apague sin que lo note un test. Descartado: confiar solo en el diff.
4. **`npm run build` es un smoke check.** No es una prueba del cambio. Se corre porque CI lo corre (`deploy.yml:28`) y porque se borran imports. Descartado: omitirlo.
5. **El `_` como prefijo de parámetro sin uso** no choca con ninguna regla: el repo no tiene linter (`.factory/config.toml`). Descartado: `(_, v)`, que es equivalente pero se lee peor junto a la otra lambda.
