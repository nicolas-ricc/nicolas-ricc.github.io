**Files:**

- Test: `src/lab/page.test.ts` (new `describe` after `"?speed= en el lab (#114)"`)

**Interfaces:**
- Consumes: `MAX_SPEED` exported from `src/lab/page.ts` and `bloomFromSearch(search: string): BloomMode | null` (`src/lab/page.ts:17`), both already in the test file's `./page` import (`src/lab/page.test.ts:5`); `ROOT` and `readFileSync` already in the test file.

- [ ] **Step 1: Write the failing test** in `src/lab/page.test.ts`:

```ts
describe("lab world help documents URL parameters (#180)", () => {
  const hostTag = (p: string): string => readFileSync(`${ROOT}lab/${p}.html`, "utf8").match(/<div id="lab-host"[^>]*>/)?.[0] ?? "";
  const label = /\baria-label="([^"]*)"/.exec(hostTag("world"))?.[1] ?? "";
  it("lists ?bloom= with the modes it forces", () => {
    expect(label).toContain("?bloom= lo fuerza al cargar: on, off o fallback.");
    for (const m of /\?bloom= lo fuerza al cargar: (\w+), (\w+) o (\w+)\./.exec(label)!.slice(1)) expect(bloomFromSearch(`?bloom=${m}`), m).toBe(m);
  });
  it("lists ?speed= with its cap and ?speed=0 freezing the clock", () => {
    expect(label).toContain(`?speed= escala el reloj de las animaciones hasta ${MAX_SPEED}; ?speed=0 lo congela.`);
  });
  it("leaves the other lab pages' help alone", () => {
    for (const p of ["blog", "resume", "portfolio", "storybook"]) {
      expect(hostTag(p), p).not.toMatch(/\?(speed|bloom)=/);
    }
  });
});
```

`hostTag` isolates the `<div id="lab-host" …>` tag the same way `src/lab/host.test.ts:11` does, so the label read is the host's even if another element with an `aria-label` is added before it. If `label` is empty the first `toContain` fails before the `!` assertions run.

## Assumptions

- **Sentence order bloom, then speed:** the same order as the `bootWorldPage` docstring (`src/lab/page.ts:39-41`). The owner's comment names speed first but fixes no order; no test asserts the order of sentences in the label.
- **"on, off o fallback" vs. "off, on, fallback":** the key-6 sentence lists the rotation order (`BLOOM_CYCLE`, `src/lab/page.ts:14`); the parameter sentence keeps the order of `bloomFromSearch`'s docstring (`src/lab/page.ts:16`). No test compares the two.
- **No pipes in the label:** the docstring's `on|off|fallback` is developer notation; the `aria-label` is read aloud, so the modes are a Spanish list. Rejected: copying `on|off|fallback` verbatim (voiced as "barra vertical"). Neither the issue nor the owner's comment fixes the notation.
- **Red evals commit:** the pipeline running this plan prescribes committing the failing tests before implementing (as the #167 plan did); `npm test` green is the bar at the end of each task, not for that commit.
- **Other pages' hosts exist:** `src/lab/host.test.ts:9-14` already fails if any of the five pages lacks a `<div id="lab-host"` with an `aria-label`, so the "leaves the other lab pages' help alone" case cannot pass vacuously without that test failing.
- **Bloom modes checked through `bloomFromSearch`, not by importing `BLOOM_CYCLE`:** `BLOOM_CYCLE` is not exported; exporting it only for a test widens the module API. Feeding each listed mode to the public parser gives the same drift protection as `MAX_SPEED` gives the speed sentence.
- **Half-done state:** if Step 4 fails, the only uncommitted change is `lab/world.html`; `git checkout lab/world.html` returns to the evals commit, which already holds the test.

- **`fix` type:** the issue reports drift between runtime help and the documented behaviour, as #167's a11y change used `fix`.
- **Literal `?` in the label**: screen readers read it as text; the README and docstring use the same notation, so the help matches the source help word for word.
