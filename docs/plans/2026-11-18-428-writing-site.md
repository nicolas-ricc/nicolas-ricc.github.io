# writingSite, COVER_FOCUS_U 0.39, narrow zoneView and the site decided by #app (#428) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The site picks the Writing site from the host (`writingSite(w, h)`), the narrow-screen focus moves to 0.39, `zoneView("blog")` shows the active site's sign, and `main.ts` decides the site from `#app` so it changes with the viewport only, never during the zone transition.

**Architecture:** `writingSite` is a pure rule in `src/world/signs.ts` over `coverView` and `signBox(BLOG_SIGNS.wide)`. `zoneFrame`/`zoneView` take an optional `site` (default `"wide"`); Blog's tall frame reaches y 440 and `zoneView("blog")` then shifts the camera the minimum needed to keep the active sign's box inside the host. `main.ts` holds a mutable `site`, recomputed by `syncSite()` from `#app` at boot and in the existing `ResizeObserver` callback.

**Tech Stack:** TypeScript, Vitest, PixiJS v8 (runtime only), agent-browser for the manual check.

**Spec:** issue #428 ("Diseño (decidido)" and "Criterios de aceptación" are binding), within `docs/superpowers/specs/2026-11-18-composicion-responsive-design.md` §2.4, §3.1, §3.2, §5.1–§5.3. Parent story #423.

## Global Constraints

- `COVER_FOCUS_U = 0.39` (was 0.35).
- `export const WRITING_SITE_MARGIN = 8` in `src/world/signs.ts`; `main.ts` drops its `LABEL_MARGIN` and imports this one.
- `writingSite(w, h)`: `"wide"` iff the host box of `signBox(BLOG_SIGNS.wide)` under `coverView(w, h)` lies ≥ `WRITING_SITE_MARGIN` px from all four edges (`≥`, inclusive); else `"tall"`. No aspect threshold.
- `zoneFrame(frame, site = "wide")`: Blog's box is `x ZONE_SPLIT_X..WORLD.x1, y WORLD.y0..440` when `site === "tall"`; unchanged with `"wide"` and for every other frame.
- The 14 sizes (§5.1): `[1920,955],[1600,900],[1440,900],[1366,1024],[1280,900],[1180,820],[1024,768],[1000,1000],[900,1000],[820,1180],[768,1024],[430,932],[390,750],[360,740]`.
- The site is decided with `#app` (`clientWidth`, `clientHeight`), never with `#canvas-host`.
- Code, comments and test names in English (`src/english.test.ts`).
- The 2026-11-17 spec is history: its tables are not rewritten; `docs.test.ts` pins its literals.

## Technical decisions (declared; not in the issue's design)

1. **`zoneView("blog")` keeps the sign inside.** Measured on the base branch with focus 0.39: extending Blog's tall box to y 440 alone leaves Writing at host x −46..89 in 768×955 (and off-host in every portrait size: the floor case centers on the zone box, ~230 projected units east of the tall sign). Spec §3.2 allows "se extiende la caja de Blog o se acota con el cartel", so `zoneView` does both: after the usual fit/floor and clamps, for `zone === "blog"` it shifts the view by the minimum that puts `signBox(zoneSigns(site).blog)` at ≥ `WRITING_SITE_MARGIN` px from each host edge (per axis; no shift on an axis where the box plus margins is larger than the host), then clamps to cover and bleed again. Probe: in all 20 sizes of `view.test.ts` plus the 14 the sign ends inside; shift is 0 wherever it already fitted (1920×955, 1600×900, 1280×900, 1024×768, 390×300 …), so the landscape framings do not move.
2. **No import cycle.** `zoneView` (in `view.ts`) needs the sign box, and `signs.ts` imports `view.ts` (`unproject`, and now `coverView` for `writingSite`). So `signBox` (with its WeakMap memo) and `WRITING_SITE_MARGIN` move to a new pure module `src/world/sign-box.ts` that imports only `project` and the types `SignSpec`/`ScreenBounds`; `signs.ts` re-exports both (`export { signBox, WRITING_SITE_MARGIN } from "./sign-box"`) and keeps `type ScreenBox`, so every importer is unchanged. `view.ts` imports from `./sign-box` and `BLOG_SIGNS` from `../scenes/sign-platform`. Graph: `signs → view → sign-box`, `signs → sign-box`; no cycle.

## Review Focus

1. A host of 0×0 (before layout) must not throw: `writingSite(0, 0)` returns `"tall"`. Test in Task 2.
2. A host where the wide box sits exactly at the margin counts as wide (inclusive `≥`); covered by the stability sweep (exactly one change between 700 and 1700 px at 900 px high). Test in Task 2.
3. Opening a zone at 1600×900 (host shrinks to the 2fr column, `#app` does not) must not move the platform: agent-browser check in Task 4 (transform of `a[data-zone=blog]` on the map before and after a round trip to `/area/blog/`).
4. A site change with a zone open must re-target the camera with the new site's `zoneView` and re-place the labels: `syncSite()` runs before `targetFor` in the observer callback. Agent-browser rotation 900×1440 ↔ 1440×900 in Task 4.
5. `zoneView("blog", w, h, "wide")` must stay what it was wherever the wide sign already fits (no gratuitous camera move on desktop): Task 3 test pins equality with the pre-shift view at 1920×955 and 1600×900.
