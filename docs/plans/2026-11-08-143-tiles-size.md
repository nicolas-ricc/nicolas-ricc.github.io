# Tile size as a parameter of `tiles()` (#143): implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `tiles()` takes an optional tile side `size` (default `TILE`), and the paved patio of `courtyardO` uses `size = 2`, so its 11×5 patio reads as paving (6×3 tiles instead of 2×1).

**Architecture:** `tiles(rng, r, z, mat, tone = brokenTone, size = TILE)` in `src/scenes/city-pieces.ts` walks `r` in steps of `size` instead of `TILE`, clipping the last row and column to `r` as today. With the default, the loop is the same as today's, so every current caller's output is byte-identical. `courtyardO` (`src/kit/forms/courtyard.ts:56`) passes `brokenTone, 2`. More tiles mean more draws from the `rng` shared with `city()`, so the blocks after a paved `courtyardO` change their details. Triage accepted this. The world baselines that move are re-recorded once.

**Tech Stack:** TypeScript, Vitest.

**Spec:** issue #143, the triage "Agent Brief" comment of 2026-11-08 (behaviour, acceptance criteria, out of scope).

## Global Constraints

- Signature: `tiles(rng: Rng, r: Rect, z: number, mat: Material, tone?, size?)`. `size` goes last, with `TILE` as its default.
- With `size` omitted, the output of every current caller is identical byte for byte.
- `courtyardO` passes `size = 2`. No other recipe or caller changes (`src/city/fixed.ts`, `src/kit/forms/landmarks.ts` `library`, `src/kit/forms/lowrise.ts` `eatenRuin`, `src/kit/forms/modern.ts` `campus`, `src/scenes/tech.ts`).

- The `world-baseline.test.ts` hashes that change are updated, and the PR justifies them with before/after screenshots.
- Out of scope: changing the size in other recipes, and moving `tiles` out of `src/scenes/`.
- `npm test` and `npm run typecheck` green.

## Assumptions

- A1. `size` must be positive. `tiles` throws a `RangeError` when `!(size > 0)`, because `size <= 0` or `NaN` would make the loop never end, or emit nothing without saying so. `Infinity` is allowed: it is the natural "one tile clipped to the rect" case (`Math.min(Infinity, …)`). No caller passes such a value. Rejected: clamping silently, and rejecting `Infinity` (grilling Q7).
- A2. To pass `size`, `courtyardO` also passes `brokenTone` explicitly, since it is the default today. Rejected: reordering the parameters, which the brief's signature fixes.
- A3. The pinned fingerprints above are the "before" oracle. A test of the form "default equals `size = TILE`" alone would not prove anything about the old output.
- A4. The hashes that are expected to move are `WORLD`, `ZONES.cv` and `RESUME_LAB` (the world's `city()` has paved `courtyardO` patios, per `docs/plans/2026-11-08-142-zocalo-por-ground.md`). `ZONES.portfolio`, `ZONES.blog` and `PIECES` must not move. If anything else moves, stop and investigate. Do not re-record.
- A5. The comment above `WORLD` in `world-baseline.test.ts` gains a `#143` line, following the `#142` precedent.
- A7. Task 1's commit is green on its own: with `size` omitted the loop is today's (`src/scenes/city-pieces.ts:37-38`, where `TILE` appears only in the step and the clipping), so no baseline moves until task 2.
- A8. The before/after screenshots for the PR (stage 8 of the pipeline, not a plan task) are taken with `agent-browser` at viewport `1600 900 2` (CLAUDE.md) on `/lab/world.html`, from an `origin/main` worktree ("before") and from the branch ("after"), on a world-seed block with a paved `courtyardO`. - A6. No ADR and no `CONTEXT.md` entry: this adds a parameter, not a domain term.

## Review Focus

1. **Non-integer rects with `size = 2`.** Patio coordinates are half-integers (6.5). The clipped edge must end exactly at `r.x + r.w`. Pinned: the task 1 test checks every tile's bounds against the rect, and that the tiles cover its area.
2. **Size larger than the rect.** `size = 2` on a 1×1 rect must give one 1×1 tile. Pinned: task 1.
3. **Degenerate size.** `size` of 0, a negative number or `NaN` must throw, not hang. An empty rect (`w` or `d` ≤ 0) gives no triangles, as today: the loop condition is unchanged. Pinned: task 1 (A1).
4. **Tone draws per tile.** Each tile still draws two tones (one per triangle). Pinned: task 1, where the 6×3 case has 36 triangles.
5. **Baselines moving outside `cv`.** Pinned: the untouched `portfolio`, `blog` and `PIECES` hashes (task 2).

### Task 1: `size` parameter on `tiles`

**Files:**
- Modify: `src/scenes/city-pieces.ts:33-42`
- Test: `src/scenes/city-pieces.test.ts`

**Interfaces:**
- Produces: `tiles(rng: Rng, r: Rect, z: number, mat: Material, tone: (rng: Rng) => number = brokenTone, size: number = TILE): Solid`. It throws `RangeError` if `!(size > 0)`. The doc comment says the tiles are `size`×`size`.

- [ ] **Step 1: Write the failing tests** in `city-pieces.test.ts`, as a new `describe("tiles")`:
  - `"with size omitted, the output is the one before #143"`: the three `tiles` fingerprints above (`304b66d6`, `dd78d6ad`, `a21d17ed`), and the `library`/`campus`/`eatenRuin` ground fingerprints for seeds 1..3 (the exact lot and style above).
  - `"size = 2 on an 11×5 rect gives 6×3 tiles clipped to the rect"`: on `{ x: 6.5, y: 6.5, w: 11, d: 5 }`, `tris.length === 36`. Take each tile's bounding box (pairs of triangles). There are 18 distinct boxes, each inside the rect within 1e-9, each with side ≤ 2. Their areas sum to 55. The sorted distinct widths are `[1, 2]` and depths are `[1, 2]`. Every `z` is the given z.
  - `"a size larger than the rect gives one tile, clipped"`: `tiles(rng, { x: 0, y: 0, w: 1, d: 1 }, 0, "paving", brokenTone, 2).tris.length === 2`, with all points in [0, 1].
  - `"a non-positive size throws"`: `0`, `-1` and `NaN` each throw `RangeError`. `Infinity` gives the same 2 triangles as one rect-sized tile.
- [ ] **Step 2: Run** `npx vitest run src/scenes/city-pieces.test.ts`. Expected: the size tests FAIL (with an extra argument the output still uses 6, and nothing throws). The fingerprint test PASSES (it is the oracle).
- [ ] **Step 3: Implement** by replacing `TILE` with `size` in the loop and the clipping, and adding the guard.
- [ ] **Step 4: Run** the same file. Expected: PASS.
- [ ] **Step 5: Commit** `feat(#143): tiles takes an optional tile size`.
