## Decisions (from the planner comment, restated so the implementer needs nothing else)

1. **What each entry says** (facts verified in the code; wording is the implementer's):
   - **Lot** (Lote): the rectangle a recipe draws inside: `x y w d`, the surface height `z` it rests on, the `open` sides (`Side`: `n s e w`; avenue, water or plaza frontage) and `maxH`, the height cap above `z`. The zoning hands out one per block (`Placed.lot`); `waterTowerLot` and `FOOTBRIDGE_LOT` are their own lots; the lab uses 24×18 lots (`KIT_LOT`), or the `LAB_LOTS` size for the recipes that need one.
   - **Piece** (Pieza): what a recipe returns: `solids`, `ground` (painted before every solid), `accents`, plus the `walls`, `windows` and `slots` it publishes for the lights, an optional `courtyard` and an optional `landmarkTop`. `emptyPiece` starts one; `addBuilding` adds a solid and publishes its walls and windows; `liftPiece` raises it; `seat` sets it on its lot (see Plinth). `src/city/lights.ts` reads `windows`, `slots` and `walls`.
   - **Recipe** (Receta): `Recipe = (lot, rng, style) => Piece`, drawing relative to `lot.z`. `RecipeDef` registers one: `name`, `recipe`, `family` (`modern`, `courtyard`, `composite`, `curved`, `lowrise`, `landmarks`) and the optional `landmark` flag. `RECIPES` concatenates the six families; `recipe(name)` looks one up and throws on an unknown name. A common recipe stays under `recipeCap(lot)` = `min(lot.maxH, RECIPE_MAX_H)` (18). The geometric helpers the recipes use (`prism`, `tiles`, `PLINTH_H`) come from `src/scenes/city-pieces.ts`; the glossary states that and no rule about it. `src/scenes/city.ts` seats `recipe(p.recipe)` per placed block.
   - **Landmark recipe** (receta landmark): back-reference to the zone Landmark first. A `RecipeDef` with `landmark: true`: the seven of `src/kit/forms/landmarks.ts` (`LANDMARKS`) and three of `modern.ts` (`glassTower`, `classic`, `constructionSite`). Its cap is `LANDMARK_MAX_H` (24) instead of 18; `fitToCap` flattens a piece in z, relative to `lot.z`, so it fits `min(lot.maxH, LANDMARK_MAX_H)`. It publishes `Piece.landmarkTop`, its highest point, which `fitToCap` and `liftPiece` carry along; no scene code reads it today, only tests (`landmarks.test.ts`, `kit.test.ts`). The `landmark` flag itself is read only by the generic test `kit.test.ts`, to choose the cap. `src/city/zoning.ts` gives the fixed blocks, the `district` neighborhood, `waterTowerLot` and `FOOTBRIDGE_LOT` a `maxH` of `LANDMARK_MAX_H`.
   - **Style** (Estilo): the look a recipe receives: `id` (`StyleId`: `downtown bars residential civic riverside district`), `mat`, `trim`, `roof`, `tone`, `floorH`, `window` (`windowWarm` / `windowCool`). `STYLES` holds one per neighborhood with `tone` 0; `src/scenes/city.ts` overrides `tone` per block.
   - **Wall** (Pared): a facade that faces the camera, published by `addBuilding` for each wall of the solid (`visibleWalls`) whose normal has x > 0 or y > 0: `pts`, `normal`, `floorH` (the wall height over the facade's floors) and `building` (index of the solid in `Piece.solids`). The civic neighborhood's bathed facades read them.
   - **Window** (Ventana): a lit-window candidate on a wall, from `facadeWindows`: `pts`, `floor`, `wall` (the wall normal) and `building`. `src/city/lights.ts` picks which are lit.
   - **Slot** (no Spanish name; the specs say "slot"): a place for a neon or a sign on a wall: `pts`, `wall` (normal), `side`, `kind` (`neon` | `sign`), `shop` (index of the ground-floor shop). `lowrise` publishes `neon` slots per shop when the lot has open sides; `southSign` builds the south-face `sign` slot of towers at least `SIGN_MIN_H` (12) high. `src/city/lights.ts` lights the bars' neons; `src/scenes/city.ts` lights the district's signs.
2. **`Code:` lines**, exactly these files and identifiers (each one grep-verified):
   - Lot: `src/kit/types.ts` (`Lot`, `Side`), `src/city/zoning.ts` (`Placed`, `waterTowerLot`, `FOOTBRIDGE_LOT`), `src/lab/kit-scene.ts` (`KIT_LOT`).
   - Piece: `src/kit/types.ts` (`Piece`), `src/kit/piece.ts` (`emptyPiece`, `addBuilding`, `liftPiece`, `seat`), `src/city/lights.ts`.
   - Recipe: `src/kit/types.ts` (`Recipe`, `RecipeDef`), `src/kit/index.ts` (`RECIPES`, `recipe`, `LAB_LOTS`), `src/kit/piece.ts` (`RECIPE_MAX_H`, `recipeCap`), `src/scenes/city.ts`.
   - Landmark recipe: `src/kit/piece.ts` (`LANDMARK_MAX_H`, `fitToCap`), `src/kit/types.ts` (`RecipeDef.landmark`, `Piece.landmarkTop`), `src/kit/forms/landmarks.ts` (`LANDMARKS`), `src/kit/forms/modern.ts`, `src/city/zoning.ts`.
   - Style: `src/kit/types.ts` (`Style`, `StyleId`), `src/kit/styles.ts` (`STYLES`), `src/scenes/city.ts`.
   - Wall: `src/kit/types.ts` (`Wall`), `src/kit/piece.ts` (`addBuilding`), `src/iso/solids.ts` (`visibleWalls`), `src/city/lights.ts`.
   - Window: `src/kit/types.ts` (`Window`), `src/iso/facade.ts` (`facadeWindows`), `src/kit/piece.ts` (`addBuilding`), `src/city/lights.ts`.
   - Slot: `src/kit/types.ts` (`Slot`), `src/kit/piece.ts` (`southSign`, `SIGN_MIN_H`), `src/kit/forms/lowrise.ts`, `src/city/lights.ts`, `src/scenes/city.ts`.
3. **How the test reads a `Code:` line.** `codeRefs(section)` takes the section's line that starts with `Code:` and returns, for each backticked `src/…` path, the path and the backticked identifiers in the parenthesis right after it (none if no parenthesis follows). An identifier counts as present if each of its dot-separated segments occurs in the file text as a whole word (`new RegExp(`\\b${seg}\\b`)`), so `Lot` is not satisfied by `KIT_LOT` nor `recipe` by `recipeCap`; `RecipeDef.landmark` needs both `RecipeDef` and `landmark` as words. The check runs on the eight new entries only; existing entries are not this issue's.
4. **How the test cuts a section.** `section(glossary, title)`: from the line `### <title>` (exact title, end of line) up to the next line starting with `### ` or the end of the file. `section(…, "Landmark")` must not swallow `### Landmark recipe`: match the heading line exactly.

## Review Focus

1. `### Landmark` matching `### Landmark recipe` when cutting sections: the test pins the exact heading (decision 4), and asserts the zone Landmark section does not contain `LANDMARK_MAX_H`.
2. A `Code:` identifier that only exists in a different file than the one named: caught, since the check reads the named file (decision 3).
3. A typo'd path in a new `Code:` line: the file must exist (`existsSync`), asserted before the identifiers.
4. An entry placed before **Plinth** or out of order: the test asserts the heading order of the eight new titles and that they follow `### Plinth`.
5. The **Landmark** cross-reference dropped in a later edit: asserted both ways (Landmark section names `Landmark recipe`; Landmark recipe section names the zone Landmark via `Landmark of a zone`).

## Assumptions

- The **Plinth** entry already covers the brief's "Block plinth (`PLINTH_H`)": it is not duplicated, only added to the test list (planner decision 1).
- Identifier presence is checked by whole-word regex per dot-segment (decision 3), not by parsing TypeScript: the brief asks for "verificable con grep", i.e. `grep -w`. Rejected alternative: plain substring (lets `Lot` pass on `KIT_LOT`, grilling Q4) or a TypeScript AST check (more than grep).
- The test pins names, not values: a constant whose value changes (`RECIPE_MAX_H` 18 etc.) does not fail the glossary test. Rejected alternative: parse the numbers from the code; the brief asks only that identifiers exist (criterion 2).
- Prose-only claims ("no scene code reads `landmarkTop`", "the flag is read only by `kit.test.ts`") are true today (grep: `landmarkTop` and `.landmark` appear outside `src/kit/` only in tests) and are not guarded by a test; that is the nature of a glossary. Identifiers mentioned only in prose (`glassTower`, `neonSlot`) are not checked; only the parenthesised `Code:` identifiers are.
- Each entry keeps a single `Code:` line, as every existing entry does (`CONTEXT.md`, one `Code:` line per entry). A wrapped `Code:` line would make `codeRefs` read only its first line; not guarded.
- Failing test committed alone before the docs (`test(#126): evals`), as this run's pipeline prescribes; HEAD is red only between those two commits.
