# Resume (#193): el CV en PDF embebido en la zona — plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Al abrir la zona Resume (`/area/resume/`, por click o carga directa) el panel muestra el CV real (`public/cv.pdf`, copiado de `riccomini-multiverse/cv/cv.pdf`) embebido, con un botón de descarga de solo ícono, en lugar del contenido placeholder de `content/cv.json`.

**Architecture:** El PDF se copia una vez a `public/cv.pdf` (Vite lo sirve en `/cv.pdf`). `content/cv.json` gana `"pdf": "/cv.pdf"` y pierde las secciones placeholder. `renderContent` (`src/content/render.ts`), que usan tanto el boot (`src/main.ts`) como el prerender (`scripts/prerender.ts`), cambia el enlace de texto por un bloque `.pdf-viewer` con el botón-ícono y un `<object type="application/pdf">` con contenido de respaldo. El layout del bloque vive en `src/style.css`.

**Tech Stack:** TypeScript estricto, Vite, Vitest, CSS plano. Sin dependencias nuevas.

**Spec:** issue #193 (nicolas-ricc/nicolas-ricc.github.io).

## Global Constraints

- PDF fuente: `gh api repos/nicolas-ricc/riccomini-multiverse/contents/cv/cv.pdf -H "Accept: application/vnd.github.raw" > public/cv.pdf`. Se copia una vez; nada de sincronización automática.
- Servido en `/cv.pdf` (`base: "/"`).
- Botón de descarga: **solo ícono**, sin texto visible; `aria-label` y `title` exactamente `Descargar CV en PDF`; atributo `download`; ícono SVG inline; colores de la paleta.
- Todo color de `src/**/*.ts` sale de la paleta (`palette-guard.test.ts` rechaza `0x[0-9a-fA-F]{6}`): el SVG usa `currentColor` y el color lo pone `src/style.css`, con colores de la paleta (`#ffc457` = `ISO_COLORS.amber`, `#5a3d14` = `ISO_COLORS.amberBleed`, `src/map/palette-iso.ts:66-68`). `style.css` no lo revisa ningún guard, así que la regla se cumple a mano.
- Comentarios y nombres de tests en castellano; tests Vitest al lado del módulo. Commits `feat(#193): …`.
- `npm test` y `npm run typecheck` verdes al cerrar cada task.

## Decisiones técnicas (declaradas)

1. **`<object>`, no `<iframe>`.** `<object type="application/pdf">` permite contenido de respaldo: los navegadores sin visor de PDF embebido (Chrome en Android, por ejemplo) muestran un párrafo con un enlace "abrir el CV" a `/cv.pdf` en pestaña nueva. Ese enlace es de apertura, no de descarga, y solo aparece cuando no hay visor; no contradice el botón de solo ícono.
2. **Qué secciones se van.** "Experiencia" (`"Rol y fechas pendientes."`) y "Stack" son placeholder y el PDF las cubre: se quitan. "Contacto → GitHub" no es placeholder y el PDF no trae el enlace a GitHub (sus URIs son tel, mail, LinkedIn y myxomatosis.xyz): se queda. `titulo` y `descripcion` se quedan (el `h1` y el lead del panel).
3. **El botón va arriba del PDF, alineado a la derecha**, no superpuesto: el visor de Chrome tiene su propia barra arriba y un botón flotante la taparía.
4. **Tamaño del visor:** `width: 100%` y `aspect-ratio: 210 / 297` (A4), así a cualquier ancho una página entra completa a lo ancho y el panel (`#content`, que ya scrollea) se encarga del resto. "Legible a ancho de teléfono" se verifica a 390 px de ancho en el navegador headless; en un teléfono real depende del visor del sistema (verificación manual en el PR).
5. **La identidad del PDF** (byte a byte igual al de `riccomini-multiverse`) no se puede testear en CI (repo privado): el test fija que `public/cv.pdf` exista y empiece con `%PDF-`; la igualdad se verifica con `cmp` en Task 1 Step 4 y queda dicha en el PR.
6. **Carga directa de `/area/resume/`:** el prerender (`scripts/prerender.ts`) y el boot (`src/main.ts`) llaman al mismo `renderContent`; no hace falta código nuevo, se verifica en el navegador y con `npm run build` (el HTML prerenderizado debe contener el `<object>`).

## Review Focus

1. Navegador sin visor de PDF embebido (teléfono Android): debe verse un enlace para abrir el CV, no un hueco vacío → test en Task 2 (el `<object>` trae un `<a href="/cv.pdf">` de respaldo).
2. Una URL de `pdf` con caracteres HTML (`"`, `&`) no rompe el atributo → test en Task 2 (escape en `href` y `data`).
3. Zona sin `pdf` (Portfolio, Blog): no aparece ni el botón ni el `<object>` → test en Task 2.
4. Panel a 390 px de ancho: sin scroll horizontal, PDF a todo el ancho del panel, botón visible → script de navegador en Task 3.
5. Salir al mapa y volver a Resume, y la carga directa de `/area/resume/`: el CV aparece igual → script de navegador en Task 3.

```ts
/** Flecha hacia una bandeja; el color lo pone el CSS (currentColor). */
const DOWNLOAD_ICON =
  '<svg viewBox="0 0 24 24" width="20" height="20" aria-hidden="true" focusable="false" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round"><path d="M12 3v12M7 10l5 5 5-5M5 21h14"/></svg>';

function renderPdf(url: string): string {
  const u = escapeHtml(url);
  const download = `<a class="pdf-download" href="${u}" download aria-label="Descargar CV en PDF" title="Descargar CV en PDF">${DOWNLOAD_ICON}</a>`;
  // sin visor de PDF embebido (p. ej. Chrome en Android) el navegador muestra el contenido del object
  const fallback = `<p>Este navegador no muestra el PDF acá: <a href="${u}" target="_blank" rel="noopener">abrir el CV</a>.</p>`;
  return `<div class="pdf-viewer">${download}<object class="pdf-embed" data="${u}" type="application/pdf" aria-label="CV en PDF">${fallback}</object></div>`;
}
```

## Assumptions

Decisiones técnicas sin fuente escrita, decididas acá (van al PR):

1. **`<object>` en vez de `<iframe>`, `<embed>` o PDF.js.** El issue admite `<object>`/`<iframe>`. `<object>` muestra su contenido interno cuando no hay visor; `<iframe>` no tiene contenido de respaldo y PDF.js sería una dependencia nueva (~1 MB) para un archivo de 66 KB. Descartadas: `<iframe>` (hueco en blanco sin visor), PDF.js (peso y dependencia).
2. **Respaldo con texto visible** ("abrir el CV") solo cuando el navegador no tiene visor. La regla de "sin texto visible" del issue es para el botón de descarga; un hueco vacío en un teléfono contradiría "legible a ancho de teléfono". Descartada: respaldo vacío.
3. **Comportamiento en teléfonos reales** (Chrome Android, Safari iOS, Firefox Android): sin fuente en el repo ni forma de probarlo headless. Va al PR como verificación manual. El script de navegador solo prueba Chrome headless a 390 px.
4. **Visor de una página de alto** (`aspect-ratio: 210 / 297`): el PDF es A4 (`/MediaBox [0 0 595.28 841.89]`) de 2 páginas (`/Count 2`). La segunda se ve scrolleando dentro del visor. Descartado: alto de dos páginas (doble scroll largo en el panel y el visor de Chrome igual scrollea por dentro).
5. **Tests de HTML con `toContain` y regex no codiciosas**, como los de `render.test.ts` hoy, sin agregar jsdom/happy-dom. Descartado: un parser DOM solo para estos tests.
6. **Rollback:** cada task es un commit; se deshace con `git revert` de ese commit. No hace falta conservar una ruta alternativa con el enlace de texto.
