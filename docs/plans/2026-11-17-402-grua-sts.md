# Quay crane STS boom (#402): Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The quay crane gets a nearly horizontal STS boom that reaches out over the water, and `quayCraneAt` takes an options object with `light` and `reach`; the east-bank shipyard and the `grua-muelle` piece drop the tip light.

**Architecture:** One builder (`quayCraneAt` in `src/kit/forms/industrial.ts`) changes signature and geometry; its three call sites (the kit recipe `quayCrane`, `quayCranes()` in `src/scenes/shipyard-east.ts`, the `grua-muelle` exhibit in `src/lab/exhibits.ts`) adapt. No engine, crop or framing code changes.

**Tech Stack:** TypeScript, vitest, the repo's iso engine (Pixi-free).

**Spec:** issue #402 ("Decisiones heredadas" 1–5 and "Criterios de aceptación"), parent story #395 (plan comment, decision 8), `docs/superpowers/specs/2026-11-16-storybook-luces-y-encuadre-design.md` §4. Base branch `feature/395-storybook-luces-encuadre`.

## Global Constraints

- Code, comments, strings and identifiers in **English** (`src/english.test.ts`).
- New signature, verbatim: `quayCraneAt(at, dir, out, accents, opts: { z?: number; rails?: boolean; light?: boolean; reach?: number } = {})`, defaults `z 0`, `rails true`, `light true`, `reach 8`.
- Legs, cross beams, cabin and rails do not change.
- Nothing above `z + 17.5`; the mast is the topmost solid.
- Region boxes of `darsena`, `patio-contenedores` and `punta-norte` do not change.
- `npm test` and `npm run typecheck` pass.

## Decisions (technical assumptions, declared)

1. **Geometry** (`f` = unit vector toward `dir`, `T = at − 3·f`): boom `beam` from `(T, z + 12.3)` to `tip = (at + reach·f, z + 14)`, `w 0.6`, `h 0.5`; mast `prism(at.x − 0.2, at.y − 0.2, z + 12, 0.4, 0.4, 5.5)`; two stays `beam` `w 0.2`, `h 0.2`, from the mast head to `tip` and to `(T, z + 12.3)`. The light housing goes. Boom, mast, stays and cabin carry `interlock`.
2. **Stay anchor at `z + 17.4`, not 17.5.** A sloped `beam`'s bounds rise `h/2 · cos θ` above its axis end (`src/iso/solids.ts` `beam`), so a stay anchored at 17.5 would top out at ≈ 17.59 and be the topmost solid, against inherited decision 2 ("the mast is the topmost solid") and the criterion "its tallest solid is at z 17.5". Anchoring the axis half a section (0.1) below the mast top keeps both stays ≤ 17.5 and the mast topmost. Rejected: shortening/lowering the mast (changes the inherited 17.5).
3. **Recipe reach:** `half = (dir === "s" ? lot.d : lot.w) / 2`, `reach = Math.min(8, half − 0.5)`. With `LAB_LOTS.quayCrane` (8 × 8) that is 3.5.
4. **Call sites:** `quayCranes()` passes `{ rails: false, light: false }`; the exhibit passes `{ light: false }`; the recipe passes `{ z: lot.z, reach }` (light on by default).
5. **Exhibit `h`s** stay as they are if `framing`/`neighbors` pass (they only require `h ≥ max(inside, accents)` and `h ≤ max(withAnim, accents) + 8`); only the comments that quote measured values (`patio-contenedores`: "inside 18, accents 16"; `grua-muelle`: "one cyan dot on the boom tip") are rewritten with values re-measured with `measure`.
