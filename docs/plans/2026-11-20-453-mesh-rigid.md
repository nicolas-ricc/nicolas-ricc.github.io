# Engine: `mesh` primitive of arbitrary faces and rigid transform (`rigid.ts`) (#453) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `Solid` of `kind: "mesh"`: arbitrary planar faces that keep their given winding, their list order and their own material and tone offset. Plus a pure rigid-body transform (`src/iso/rigid.ts`), so the Writing raft (#454–#456) can pitch and roll as one body with coplanar decals.

**Architecture:** `facesOf` gets a `mesh` case that maps each `MeshFace` to a `Face` whose normal is `polygonNormal(pts)`, used as is. `tessellateAll`, `tessellate`, `bounds`, `shadowPolygon`, `sortByDepth` and `buildRenderList` all go through `facesOf`, so they need no new case. `translate` and the private `mapZ` of `src/kit/piece.ts` are exhaustive switches over `kind`, so each gets a `mesh` case. `rigid.ts` has no imports beyond `geometry.ts`: it holds the Rodrigues rotation and the pitch, roll and heave pose about a centre.

**Tech Stack:** TypeScript, Vitest (node, no Pixi).

**Spec:** issue #453 ("Decisiones heredadas" and "Criterios de aceptación" are binding); story #451, plan comment, D3.

## Global Constraints

- Type, verbatim: `{ kind: "mesh"; faces: MeshFace[]; mat: Material }` and `export interface MeshFace { pts: Vec3[]; mat?: Material; toneOffset?: number }`. A face's `mat` defaults to the solid's `mat`.
- Face normal = `polygonNormal(face.pts)` **as is**: no orientation by centre, no flip. Tone = `shadeTone(normal)`. `toneOffset` = the face's (default 0), plus `s.tone` through `tessellateAll`.
- `isFlat` stays false for `mesh`. Culling is the usual `dot(normal, VIEW_DIR) > 0`.
- Faces are emitted in list order, never re-sorted.
- The `bounds`, `shadowPolygon`, `sortByDepth`, `buildRenderList` and `screenHull` code is not touched. `src/lab/crop.ts` gets no case.
- `src/iso/rigid.ts` exports `RAFT_U = (√½, −√½, 0)`, `RAFT_N = (√½, √½, 0)`, `rotateAbout(axis: Vec3, angle: number): (p: Vec3) => Vec3` (Rodrigues, unit axis, right-hand rule: `rotateAbout(z, π/2)` maps (1, 0, 0) to (0, 1, 0)) and `rigid(pts: readonly Vec3[], centre: Vec3, pitch: number, roll: number, dz: number): Vec3[]`. Angles are in radians. Pitch is applied first, then roll, then `dz`.
- Engine tests do not use Pixi (`src/iso/pixi-free.test.ts`). Code, comments and test names are in English (`src/english.test.ts`).
- No existing test changes its result. `npm test` and `npm run typecheck` are green.

## Technical decisions (declared; not in the issue)

1. **Pitch sign.** The issue writes `R = Rot_u(roll) · Rot_n(pitch)` and also pins a test: "pitch raises `centre + 10·u` by `10·sin(pitch)`". Under the right-hand `rotateAbout` the issue also pins, `Rot_n(θ)` takes u to `u·cos θ + (n × u)·sin θ`, and `n × u = (0, 0, −1)`: a positive θ *lowers* +u. Roll is consistent: `u × n = (0, 0, 1)`, so `Rot_u(roll)` raises +n. The test is the more specific statement, so it wins. `rigid` applies `rotateAbout(RAFT_N, −pitch)`, then `rotateAbout(RAFT_U, roll)`, and its JSDoc says "positive pitch raises the +u end; positive roll raises the +n end". Downstream (#456) both angles oscillate symmetrically (±1.5°, ±1°), so the sign changes no visible outcome.
2. **`mapZ` in `src/kit/piece.ts` gets a `mesh` case.** Its `default` branch reads `s.at`, which a mesh does not have (a typecheck error). The case maps every point's z through `z` and leaves `k` out: a mesh has no height field. That is the same as `ground`.
3. **`translate.test.ts` fixture table.** A `mesh` fixture is added to `SOLIDS`, so the shared round-trip tests also cover it. The guard "the fixtures cover the twelve kinds" becomes "thirteen", because it counts kinds. The other existing tests keep their result.
4. **`rigid` returns new objects.** It never mutates `pts`. With 0, 0, 0 the copies are equal to the input but are not the same objects.

5. **`rotateAbout` does not normalize its axis.** The issue says "eje unitario", and the only callers pass `RAFT_U`, `RAFT_N` or the unit z axis. Rejected alternative: normalizing on every call, which spends cycles on every point of every pose for a case nobody has.
6. **The `translate` case is folded into Task 2.** Without it, Task 2's commit would leave the typecheck red: `translate.ts:14` has an exhaustive `switch`, and `deploy.yml` runs `npm run typecheck`.

## Review Focus

- **A clockwise face** keeps its inverted normal (it is not fixed), so a face pointing −z is culled. Test in Task 2.
- **A coplanar decal at the end of the list** comes out after its receiving face, with the same tone and `toneOffset`. Test in Task 2.
- **A degenerate face** (collinear or repeated points: `polygonNormal` returns (0, 0, 0)) gets tone `shade` and is culled by `tessellate` (dot = 0). The mesh does not throw and `bounds` still counts its points. Test in Task 2: "a degenerate face is culled and does not throw".
- **An empty `faces` list**: `tessellateAll` returns `[]`, and `buildRenderList` emits no face and no shadow (no points above 0). Test in Task 3: "an empty mesh emits nothing".
- **`rigid` with a centre off the origin**: the distance to the centre is preserved, not the distance to the origin. Covered by the rigid preservation test in Task 1, which uses centre (5, −3, −1).

**Files:**

**Interfaces:**
- Consumes: `Vec3`, `v3`, `dot` from `src/iso/geometry.ts`.
- Produces: `RAFT_U: Vec3`, `RAFT_N: Vec3`, `rotateAbout(axis: Vec3, angle: number): (p: Vec3) => Vec3`, `rigid(pts: readonly Vec3[], centre: Vec3, pitch: number, roll: number, dz: number): Vec3[]`.

- [ ] **Step 1: Write the failing tests** (`describe("rigid")`), all at ±1e-9 unless noted:
  - `RAFT_U and RAFT_N are unit and perpendicular`: `|RAFT_U| = |RAFT_N| = 1`, `dot = 0`.
  - `rotateAbout(z, π/2) maps (1, 0, 0) to (0, 1, 0)` (±1e-12).
  - `zero angles and dz return equal copies`: `toEqual(pts)` and `result[i] !== pts[i]`.
  - `preserves distances between points and to the centre`: 5 arbitrary points, centre (5, −3, −1), pitch 0.03, roll 0.02, dz 0. Every pairwise distance and every distance to the centre is unchanged.
  - `pitch raises the +u end and moves nothing along n`: centre C, `p = C + 10·RAFT_U`, `q = C − 10·RAFT_U`, pitch 0.03. `p'.z − p.z = 10·sin(0.03)`, `q'.z − q.z = −10·sin(0.03)`, and `dot(p' − C, RAFT_N) = 0`.
  - `roll raises the +n end and moves nothing along u`: `C + 10·RAFT_N` rises by `10·sin(0.02)` with roll 0.02, and `dot(p' − C, RAFT_U) = 0`.
  - `dz adds to z`: angles 0, dz 0.1 → every z + 0.1, x and y unchanged.
- [ ] **Step 2:** `npx vitest run src/iso/rigid.test.ts` → FAIL (module missing).
- [ ] **Step 3: Implement** with Rodrigues: `p·cos + (k × p)·sin + k·(k·p)·(1 − cos)`. `rigid` applies `p' = C + Rot_u(roll)(Rot_n(−pitch)(p − C)) + (0, 0, dz)` (decision 1). The JSDoc states the sign convention.
- [ ] **Step 4:** `npx vitest run src/iso/rigid.test.ts` → PASS.
