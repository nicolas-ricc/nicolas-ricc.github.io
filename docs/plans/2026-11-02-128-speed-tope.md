# `?speed=` con tope en el lab (#128): plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** que un `?speed=` enorme y finito (`1e12`) no congele la pestaña del lab ni la del storybook.

**Architecture:** desde #114 las dos páginas leen la velocidad con un único helper, `speedFromSearch(search)` en `src/lab/page.ts:23` (`src/lab/page.ts:81`, `src/lab/storybook.ts:136`). El issue cita la lectura anterior, `Number(...) || 1`, que ya no existe. El helper ya devuelve 1 para `Infinity`, para los negativos y para lo no numérico. Le falta un tope superior: se agrega la constante exportada `MAX_SPEED = 100`, y todo lo que la supere vale 1, igual que los demás valores fuera de rango. No cambia nada en los animadores.

**Tech Stack:** TypeScript, Vitest.

**Spec:** issue #128.

## Global Constraints

- Rango del issue: "clamp `speed` in both lab pages to a sane range, for example `(0, 100]`, and fall back to 1 otherwise".
- Se mantiene lo de #114: `?speed=0` congela (vale 0); un valor ausente, vacío, no numérico, negativo o infinito vale 1.
- Constante: `export const MAX_SPEED = 100` en `src/lab/page.ts`, al lado de `speedFromSearch`.
- `npm test` y `npm run typecheck` en verde. El texto va en castellano, como el resto de `src/lab/`. Commits `test(#128): …`, `fix(#128): …`.

## Decisiones técnicas (declaradas)

1. **Por encima del tope vale 1, no 100.** Es lo que dice el issue ("fall back to 1 otherwise") y lo que ya hace el helper con cualquier otro valor inválido. Recortar a 100 sería más silencioso: alguien que escribe `?speed=1e12` recibiría 100 sin darse cuenta.
2. **El 0 sigue dentro del rango.** El `(0, 100]` del issue es un ejemplo, y #114 (ya en main) fijó que `?speed=0` congela. El rango efectivo queda `[0, 100]`.
3. **Por qué 100 alcanza.** El Ticker de Pixi acota `deltaMS` a 100 ms (CLAUDE.md), así que con speed 100 cada tick recibe como mucho 10 s simulados. `city-anim` hace del orden de `dt / 4000` vueltas (issue), o sea unas 3 por tick.

## Review Focus

1. Exactamente `?speed=100` pasa (vale 100): el límite está incluido (test en Task 1).
2. `?speed=100.0001` y `?speed=1e3` valen 1 (test en Task 1).
3. `?speed=1e12` y `?speed=1.7976931348623157e308` (el finito máximo) valen 1 (test en Task 1).
4. Siguen valiendo los casos de #114: `0` congela, `Infinity` y los negativos valen 1 (son los tests que ya existen).
5. A la velocidad máxima, un tick de los animadores reales termina con tiempo acotado y sin excepciones (test de integración en Task 1).

describe("?speed= con tope (#128)", () => {
  it("el tope es 100 y está incluido", () => {
    expect(MAX_SPEED).toBe(100);
    expect(speedFromSearch("?speed=100")).toBe(100);
    expect(speedFromSearch("?speed=99.5")).toBe(99.5);
  });
  it("por encima del tope vale 1", () => {
    expect(speedFromSearch("?speed=100.0001")).toBe(1);
    expect(speedFromSearch("?speed=1e3")).toBe(1);
    expect(speedFromSearch("?speed=1e12")).toBe(1);
    expect(speedFromSearch("?speed=1.7976931348623157e308")).toBe(1);
    expect(speedFromSearch("?speed=1e12&speed=5")).toBe(1); // URLSearchParams.get toma el primero
  });
  it("el tope se compara después de parsear con Number()", () => {
    expect(speedFromSearch("?speed=1e2")).toBe(100);
    expect(speedFromSearch("?speed=%201e2%20")).toBe(100);
    expect(speedFromSearch("?speed=100abc")).toBe(1);
  });
  it("la ayuda documenta el tope", () => {
    expect(pageSrc).toMatch(/\?speed=.*100/);
    expect(readFileSync(`${ROOT}src/lab/storybook.ts`, "utf8")).toMatch(/\?speed=[\s\S]{0,80}100/);
    expect(readFileSync(`${ROOT}README.md`, "utf8")).toMatch(/`\?speed=`[^\n]*\n?[^\n]*100/);
  });
  it.each([false, true])("a velocidad máxima un tick largo de los animadores termina pronto (reducedMotion %s)", (reducedMotion) => {
    const { animators } = assembleWorld(undefined, { reducedMotion });
    const pieces = EXHIBITS.flatMap((e) => (e.kind === "piece" && e.animate ? [e.animate({ reducedMotion })] : []));
    const dt = 100 * MAX_SPEED; // deltaMS acotado por Pixi (_maxElapsedMS) × tope
    const t0 = performance.now();
    for (let i = 0; i < 10; i++) for (const a of [...animators, ...pieces]) a.tick(dt);
    expect(performance.now() - t0).toBeLessThan(2000);
  });
});

## Assumptions

Decisiones técnicas sin fuente escrita, tomadas en la revisión del plan (etapa 2). Van también en la descripción del PR.

- **A1. El time-lapse no cambia.** El método de CLAUDE.md llama al listener del ticker con un `deltaMS` fijo, y ese `deltaMS` se sigue multiplicando por `speed`, que ahora es como mucho 100. Quien quiera más tiempo simulado repite llamadas. No se agrega ninguna guarda en `stage.tick`: el issue acota la lectura de la URL, no el reloj.
- **A2. CLAUDE.md no se toca.** Su nota "`?speed=N` rinde ~0,2·N" sigue siendo cierta para N ≤ 100, y ningún documento ni script usa un `?speed=` mayor que 100 (grep sobre el repo). Se descartó documentar el tope ahí: README y las docstrings ya lo dicen.
- **A3. Umbral del test de integración.** 10 ticks de 10 s sobre todos los animadores tardan hoy unos 12 ms. El umbral de 2000 ms deja margen para CI y aun así detecta una regresión de un orden de `dt / 4000` vueltas por tick con un `dt` mayor.
